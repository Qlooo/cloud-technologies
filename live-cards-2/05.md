# Карточка 5 — Service

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: изменить способ доступа через Service и сохранить доступность.
Исходный файл k8s/50-service.yaml: NodePort, service port 80, targetPort http (5000), nodePort 30080.
kind связывает 30080 узла с 8081 VPS. Узел не является VPS: публикация порта задаётся отдельно в infra/kind.yaml при создании кластера.

```bash
kubectl get service flask-todo -o wide
kubectl get endpointslices -l kubernetes.io/service-name=flask-todo
kubectl explain service.spec.type
kubectl explain service.spec.ports
```

При преподавателе выбери требуемый тип доступа и отредактируй Service. Для ClusterIP убери nodePort; для LoadBalancer в kind нужен отдельно установленный механизм внешнего балансировщика. Простая смена type не гарантирует внешний адрес.
Проверь и примени только Service:

```bash
nano k8s/50-service.yaml
kubectl apply --dry-run=server -f k8s/50-service.yaml
kubectl apply -f k8s/50-service.yaml
kubectl get services
```

Если поменяешь nodePort, старое отображение 30080 → 8081 перестанет соответствовать ему. Не удаляй кластер для исправления доступа.
Для демонстрации доступа к Service через другой способ можно использовать kubectl port-forward: смотри kubectl port-forward --help. Укажи service/flask-todo, свободный порт VPS и актуальный порт Service; затем соответствующий SSH-туннель компьютера.
port-forward занимает терминал и обычно направляет трафик к одному выбранному Pod; это не проверка балансировки всех реплик.

Доказательство: новое состояние Service и HTTP 200 через выбранный путь. Назови отдельно Service port, targetPort, nodePort и порт VPS.
