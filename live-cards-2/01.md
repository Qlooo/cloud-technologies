# Карточка 1 — Scaling

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: изменить число реплик 2 → 4. Изменение выполняется при преподавателе.

Синтаксис:

```bash
kubectl scale --help
```

Укажи deployment/flask-todo и параметр --replicas с числом из карточки.
Затем проверь:

```bash
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl get pods -o wide
kubectl get deployments
curl --max-time 10 -I http://127.0.0.1:8081/
```

Доказательство: четыре Pod 1/1 Running и Deployment 4/4.
Объяснение: изменилось желаемое число реплик; ReplicaSet создал недостающие Pod.
Service может направлять соединения к готовым подходящим Pod; это не гарантия строгого чередования каждого HTTP-запроса.

scale изменяет объект в кластере, файл с replicas: 2 остаётся прежним.
Если нужно сохранить новое состояние декларативно, согласуй replicas в k8s/40-deployment.yaml. Не делай apply старого файла до показа результата.
Узел остаётся один. Реплики используют общую SQLite; схема рассчитана на небольшую учебную нагрузку.
