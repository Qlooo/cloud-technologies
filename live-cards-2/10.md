# Карточка 10 — Диагностика

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Преподаватель вносит ошибку; причину ищем по фактическим событиям и журналам.

```bash
kubectl get pods -o wide
kubectl get deployments
kubectl get events --sort-by=.metadata.creationTimestamp
```

Выбери неисправный Pod и выполни kubectl describe pod с его именем. Если контейнер успел стартовать, смотри kubectl logs; при повторных падениях — logs с --previous.
Не запускай --previous для контейнера без предыдущего запуска и не ожидай application logs у контейнера, который ещё не создан.

Признаки:
- Pending: Events, доступные ресурсы, PVC Bound, ограничения размещения.
- ErrImageNeverPull: с policy Never образ отсутствует в узле; проверить тег и загрузку kind.
- ImagePullBackOff: проверить image/pull policy и доступ к registry, если они были изменены.
- CreateContainerConfigError: отсутствует нужный ConfigMap, Secret или ключ.
- CrashLoopBackOff: logs, --previous, параметры запуска, ошибки Python, права SQLite.
- Running, но HTTP недоступен: Service selector/targetPort, EndpointSlices, probe, публикация kind и SSH-туннель.

После определения причины исправь конкретное поле в исходном манифесте, проверь его через apply --dry-run=server и примени именно этот файл. При изменении только env-источника может потребоваться пересоздание Pod через rollout restart.

```bash
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl get pods
curl --max-time 10 -I http://127.0.0.1:8081/
```

Объяснение должно связать симптом, конкретную причину, исправление и доказательство восстановления.
Применение всей папки до диагностики может затереть ошибку и изменения других ресурсов — сначала выясни причину.
