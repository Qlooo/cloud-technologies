# Карточка 9 — Rollback

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: откатить Deployment к предыдущей версии.

```bash
kubectl rollout history deployment/flask-todo
kubectl get replicasets
kubectl rollout undo --help
```

Для отката нужна предыдущая отличающаяся ревизия шаблона Pod.
После нашей подготовки масштабирование и удаление Pod не создавали такую ревизию: заранее обновление ради rollback не выполнялось.
Если предыдущей версии нет, сообщи это преподавателю и уточни, какую версию он подготовил или какую требуется развернуть в рамках карточки. Не заявляй об откате без истории.

Когда предыдущая версия есть и соответствует заданию, выполни при преподавателе:

```bash
kubectl rollout undo deployment/flask-todo
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl rollout history deployment/flask-todo
kubectl get pods
curl --max-time 10 -I http://127.0.0.1:8081/
```

При необходимости --to-revision выбирает конкретную ревизию из реальной истории, а не произвольное число.
С imagePullPolicy: Never предыдущий образ должен оставаться в узле.
Доказательство: предыдущая версия приложения и образ в новом Pod.
Rollback возвращает шаблон Pod, не откатывает базу SQLite или отдельные ConfigMap/Secret, не обновляет YAML в Git. Согласуй файл Deployment с итоговым image после показа.
