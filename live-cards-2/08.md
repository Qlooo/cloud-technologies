# Карточка 8 — Rolling update

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: изменить версию image и обновить Deployment без полного отключения.
Новый образ с проверяемым отличием создаётся при выполнении карточки.
Исходный образ — flask-todo:1.0.0; не переиспользуй этот тег для новой версии.
В Deployment imagePullPolicy: Never, значит новый образ нужно сначала загрузить в kind.

Синтаксис:

```bash
kind load docker-image --help
kubectl set image --help
```

Последовательность: изменить нужный файл приложения → собрать образ под новым тегом → загрузить этот же тег через kind load docker-image с --name cloud-lab2 → указать image контейнера app в Deployment → дождаться rollout.
Сохрани изменение image и в k8s/40-deployment.yaml, если обновление делал командой set image.

```bash
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl get pods -o wide
kubectl get replicasets
kubectl rollout history deployment/flask-todo
curl --max-time 10 -I http://127.0.0.1:8081/
```

Для наблюдения обновления используй второй SSH-терминал с kubectl get pods -w, Ctrl+C завершает только наблюдение. Проверяй доступность HTTP во время перехода и покажи отличие новой версии.
Без пользовательской readinessProbe Kubernetes не проверяет готовность HTTP: при строгом требовании непрерывности нужно учесть это в операции и проверках.
Изменение только replicas не создаёт новую ревизию шаблона. Не удаляй Deployment перед rolling update.
