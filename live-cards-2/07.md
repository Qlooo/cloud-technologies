# Карточка 7 — Health check

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: добавить readinessProbe или livenessProbe при преподавателе.
В базовом Deployment пользовательских probes нет: Running 1/1 сам по себе не доказывает HTTP-проверку приложения.

```bash
kubectl explain deployment.spec.template.spec.containers.readinessProbe
kubectl explain deployment.spec.template.spec.containers.livenessProbe
```

Проверка HTTP может обращаться к пути / и именованному порту http (5000) у контейнера app. Учитывай время запуска Gunicorn и интервалы проверок; готовый изменённый YAML заранее не создан.
readiness исключает неготовый Pod из обычной маршрутизации Service, не перезапуская контейнер.
liveness после порога неудач инициирует перезапуск контейнера.
Не используй порт 8081 VPS как порт проверки внутри Pod.

```bash
nano k8s/40-deployment.yaml
kubectl apply --dry-run=server -f k8s/40-deployment.yaml
kubectl apply -f k8s/40-deployment.yaml
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl get pods
```

Выбери новый Pod и покажи его через kubectl describe pod: там должны быть параметры добавленной проверки и Ready=True.
При ошибке: Events, журналы контейнера, правильность пути/порта и таймингов.
У Kubernetes нет Docker-статуса healthy в колонке STATUS: смотри READY, Conditions и параметры probe.
