# Карточка 2 — Self-healing

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: удалить один работающий Pod и показать автоматическую замену.
Найди нужный Pod через kubectl get pods; удаляй Pod приложения, не системный Pod и не Deployment.

Синтаксис:

```bash
kubectl delete pod --help
```

После удаления конкретного Pod наблюдай:

```bash
kubectl get pods -w
```

Когда новый Pod станет 1/1 Running, нажми Ctrl+C и покажи:

```bash
kubectl get pods -o wide
kubectl get deployments
curl --max-time 10 -I http://127.0.0.1:8081/
```

Доказательство: старое имя исчезло, появилось новое имя Pod; желаемое число реплик восстановлено. Обнови браузер и проверь задачу.
Объяснение: ReplicaSet под управлением Deployment создаёт замену, а не возвращает удалённый Pod с тем же именем.
Изменение имени Pod не означает пересборку образа. Для этой проверки не нужна livenessProbe.
