# Карточка 3 — Configuration

Перед выполнением карточки — в SSH на VPS:

```bash
cd /opt/cloud-practice/flask-todo-k8s
kubectl config use-context kind-cloud-lab2
kubectl config set-context --current --namespace=cloud-lab2
kubectl get pods
kubectl get deployments
```

Это справочник для чтения после выдачи карточки. Меню ничего не применяет.
Блоки с --help и explain — справка, остальные команды выполняй осмысленно и по очереди.
Для nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.
Правки Deployment применяются через apply и создают новые Pod при изменении шаблона.
Во время карточки не применяй все исходные файлы без необходимости.


Задание: изменить настройку через ConfigMap, применить и показать эффект.
У нас реальный потребитель ConfigMap — Gunicorn, переменная GUNICORN_CMD_ARGS.
В файле k8s/10-configmap.yaml находится строка --log-level info.
Выбери новое допустимое значение уровня журнала согласно карточке.

Посмотреть текущую настройку:

```bash
kubectl get configmap flask-todo-config -o yaml
kubectl exec deployment/flask-todo -- printenv GUNICORN_CMD_ARGS
```

Во время карточки отредактируй файл:

```bash
nano k8s/10-configmap.yaml
```

Проверить и применить:

```bash
kubectl apply --dry-run=server -f k8s/10-configmap.yaml
kubectl apply -f k8s/10-configmap.yaml
kubectl rollout restart deployment/flask-todo
kubectl rollout status deployment/flask-todo --timeout=180s
kubectl exec deployment/flask-todo -- printenv GUNICORN_CMD_ARGS
kubectl logs -l app=flask-todo --tail=30 --prefix=true
```

Изменение ConfigMap не обновляет окружение уже запущенного контейнера: нужны новые Pod. Новое значение и эффект в журналах — доказательство.
Текст страницы не зависит от уровня журналирования. Не добавляй произвольный параметр, который приложение не читает.
